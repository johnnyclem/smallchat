# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - Unreleased

1.0 makes smallchat's dispatch exact by construction, and states where each guarantee stops. Resolution is separate from execution: `resolve()` proposes at most one tool and runs nothing, a tool runs by its exact provider-qualified id (`<providerId>/<toolName>`), or by intent only when one dispatch policy allows it. Arguments are validated against each tool's JSON Schema before anything runs. Compiled artifacts (format 1.0) are content-hashed and pinned to the embedder that produced their vectors, and every decision carries a replayable proof and a canonical call digest. `smallchat serve` is an MCP aggregator on the official SDK that forwards each call, by exact name, to the upstream server that owns the tool. The root entry is the inference core; compaction, CRDT memory, importance scoring and truth-ledger interop come from `@shorthand/core` 1.0, and memex and dream are experimental.

"Deterministic" in this release means one stated property: the same artifact, embedder and runtime state (registered classes, pins, semantic map, feedback, cache, options) give the same outcome, candidate order and `proofDigest` for the same intent text. LLM verifier answers and an opted-in rate limiter's window are inputs to that, not covered by it.

**Breaking**, **Added**, **Deprecated** and **Security** describe what changed; every **Breaking** entry has upgrade steps in [MIGRATION.md](./MIGRATION.md). **Fixed** lists the defects 1.0 closes by finding id: `SC-INF-NN` (inference core), `SC-SURF-NN` (CLI, MCP server, transports, channel), `SAT-NN` (satellites and packaging) and `XSUITE-NN` (cross-suite interop) refer to the suite 1.0 audit. **Known issues** lists what 1.0 does not fix.

### Breaking

#### Toolchain, versions and packaging

- **Node.js 22 or newer.** `engines.node` is `>=22.0.0` (it was `>=20.0.0`; Node 20 is end of life). CI runs Node 22 and 24. `commander` is `^15`, `better-sqlite3` `^13.0.3` (prebuilt Node-API binaries; a lockfile install still runs its `node-gyp rebuild`, which compiles nothing when a prebuild matches) and `@types/better-sqlite3` `^9.6.0`; the `package.json` that `smallchat init` scaffolds requires Node 22 too. (XSUITE-20)
- **Versions.** `@smallchat/core` and every workspace package (`@smallchat/react`, `@smallchat/nextjs`, `@smallchat/testing`, `@smallchat/playground`, `@smallchat/examples`, `@smallchat/docs`, `smallchat-vscode`) are versioned 1.0.0; the satellites' `@smallchat/core` peer range is `^1.0.0`. Every version smallchat reports — `smallchat --version`, MCP `serverInfo` (serve and the channel server), outbound `clientInfo`, the `setup` entry (`@smallchat/core@1.0.0`), the `init` dependency (`^1.0.0`) and app artifacts — is `PACKAGE_VERSION` (exported), which a test keeps equal to package.json's. Before, the package said 0.5.0 while `serve` reported 1.0.0 and the channel server and app artifacts 0.5.0, so `setup` pinned an `npx` version with no stdio `serve` and `init` scaffolds depended on `^0.5.0`, which can never resolve to the 1.0 API they use.
- **`@smallchat/core` no longer re-exports compaction, CRDT, truth, memex or dream** (importance was already subpath-only). Compaction, CRDT, importance and truth are `@shorthand/core`'s: import `@shorthand/core/compaction`, `/crdt`, `/importance`, `/truth`. `@smallchat/core/compaction`, `/crdt`, `/importance` and `/truth` stay for 1.x as `export *` re-exports of those subpaths, marked `@deprecated` (removed in 2.0). Memex and dream are the `@experimental` subpaths `@smallchat/core/memex` and `@smallchat/core/dream`, under their module names (`memexCompile` → `compile`, `loadArtifactManifest` → `loadManifest`, …). `src/package-surface.test.ts` pins the surface. (SAT-28, SAT-31)
- **Compaction type renames from `@shorthand/core` 1.0.** The snapshot pipeline's types are `CompactedSnapshot`, `SnapshotLevel`, `SnapshotCompactor`, `SnapshotDecision` and `SnapshotVerificationResult` (0.5's `CompactedState`, `CompactionLevel`, `Compactor`, `Decision` and `CompactionVerificationResult`); the old names now mean the LSM pipeline's types. MIGRATION has the table.
- **`@smallchat/core` depends on `@shorthand/core` `^1.0.0`**, published from the short-hand repository, instead of `file:./shorthand`. The published package could not be installed: `file:./shorthand` does not resolve outside this repository and `shorthand/` was not in `files`, while `dist/index.js` imports `@shorthand/core/compaction` at load time. The compaction, CRDT, importance and truth APIs (import them from `@shorthand/core`, or the deprecated `@smallchat/core` subpaths) are therefore `@shorthand/core` 1.0's, whose truth module implements Truth Format v2 (TRANSITION lines, hash chain, `sinceSeq`, the suite PROPOSAL envelope); see its MIGRATION. The full TS suite passes against the short-hand 1.0 build. (SAT-01, XSUITE-01, SC-INF-25)
- **`shorthand/` is a mirror of `@shorthand/core` 1.0.0, not a fork.** `scripts/sync-shorthand.mjs` (`SHORTHAND_DIR=../short-hand npm run sync:shorthand`) replaces it with the short-hand checkout's `src/` and `test/` trees byte for byte, derives its `package.json` (`private`, plus a `prepare` build) and records the short-hand commit and every file's sha256 in `shorthand/SOURCE`; `npm run check:shorthand`, `src/shorthand-mirror.test.ts` and a CI step fail when the tree differs from that record. The workspace satisfies the `^1.0.0` range during development (installed packages resolve the registry); its suite (`npm test --workspace=shorthand`) now runs short-hand's 681 tests, including the CRDT property tests and stenographer's Truth Format v2 fixtures. The pre-1.0 vendored copy is gone, and with it the duplicate ONNX embedding module and its `@shorthand/core/embedding` subpath: `src/embedding` is the only copy. (SAT-28, XSUITE-17)
- `npm run test:pack` (in CI after the build) packs `@smallchat/core` as it would be published, checks the tarball (dist, CLI, spec; no workspace files; no `file:`/`link:`/`workspace:` dependencies; no `dist` file whose source is gone), installs it into an empty project, loads every subpath export and `smallchat --version` there, and typechecks a Node16 TypeScript consumer of every subpath. A contract test keeps every optional platform package in the lockfile (npm 11's `npm ci` refuses one without them); `npm ci` passes on npm 10 and 11.

#### Artifact format 1.0 and embedder identity

- **Compiled artifacts are now format 1.0, with one writer and one validating loader.** `smallchat compile`, `setup`, `dream` and in-process compilation all go through `buildArtifact()`; the CLI's separate serializer (which dropped `inputSchema` and descriptions) and setup's inline copy are gone. An artifact carries `formatVersion: "1.0"`, the embedder fingerprint, every tool keyed by canonical id `<providerId>/<toolName>` with its upstream `description`, `inputSchema`, `outputSchema`, `title` and MCP `annotations`, per-provider launch specs (stdio command/args and env variable *names* only — never values — or a URL), selectors that each point at exactly one tool, and a `contentHash` (SHA-256 over RFC 8785 canonical JSON). The JSON Schema is `spec/artifact/artifact.v1.schema.json` (shipped in the package) and every load validates against it, checks internal consistency and verifies the hash. `dispatchTables`, `version`, `timestamp`, `embedding` and `stats.uniqueSelectorCount`/`mergedCount` no longer exist in the file. (SC-INF-19, SC-SURF-07)
- **Pre-1.0 artifacts are refused** with "recompile with smallchat 1.0" (JSON and SQLite), instead of loading silently with empty schemas.
- **Every load path uses the artifact's embedder.** `loadRuntime`, `serve`, `resolve`, `repl`, `inspect`/`docs` (validation only) and the playground construct the embedder named by the fingerprint (kind, model, model SHA-256, dims, maxLength, pooling, normalize), or verify an injected one, and fail with `EmbedderMismatchError` on any difference. Previously `serve` always embedded intents with the hash embedder, so artifacts compiled with the default ONNX embedder resolved nothing (every `tools/call` returned "No match"). (SC-INF-01, SC-SURF-06)
- **`LocalEmbedder` is renamed `HashEmbedder`** — it was always a hash placeholder, never a local model. `LocalEmbedder` remains as a deprecated alias (and `src/embedding/local-embedder.js` as a shim). The `@smallchat/core/embedding` subpath now points at `hash-embedder.js`. Embedders gain an optional `fingerprint`; custom embedders must declare one (kind `"custom"`) to compile or load artifacts.
- **One default embedder.** Compile, setup, dream and `serve --source <manifest dir>` share `DEFAULT_EMBEDDER_KIND` (`onnx`). `smallchat compile` no longer falls back silently when the ONNX model is unavailable: it fails and suggests `--embedder hash` (setup still falls back, and records the embedder it actually used). `smallchat.json` `compiler.embedder` is honored (it was dead because the CLI flag always had a default); `hash` is the new name, `local` is still accepted.
- **The compiler never merges distinct tools.** Tools whose embeddings are ≥ 0.95 cosine-similar (`duplicateThreshold`) are a compile error (`DuplicateToolError`) listing every pair; `--allow-duplicates` / `compiler.allowDuplicates` keeps all of them as a warning and records the pairs in the artifact. `pinSelector` is honored literally; two tools claiming one selector or one tool id is a `SelectorConflictError`. `CompilationResult.mergedCount` is removed (it miscounted); `uniqueSelectorCount` now counts selectors exactly, and `tools`/`duplicates` are new. Previously near-duplicates were silently dropped and intents for them executed a different tool. (SC-INF-08)
- **An alias phrase can belong to only one tool.** Two tools declaring the same `aliases` phrase (after NFKC, case and whitespace normalization) are a `SelectorConflictError` that names the phrase and both tools, with or without `--allow-duplicates`; before, both alias selectors embedded identically and the phrase tied between them (without the check, 1.0 reported it as a cosine-1.000 duplicate pair). `examples/rtk-manifest.json` no longer gives `run tests` to two tools.
- **`loadRuntime(path, options?)` awaits hydration** and resolves only once every tool class is registered; hydration errors (e.g. `SelectorShadowingError`) reject the promise instead of surfacing as unhandled rejections. It returns `{ runtime, artifact, embedder }`, accepts `{ embedder, runtimeOptions, compilerOptions }`, and throws instead of calling `process.exit` when a manifest directory is empty. Runtime hydration registers selectors by exact canonical (`SelectorTable.register`) so similar tools no longer fold together at load time either. (SC-INF-18, SC-SURF-28)
- **`SqliteArtifactStore` stores the 1.0 artifact** (vectors in `vec_selectors` at the artifact's dimensionality, the rest as one JSON record) and round-trips it exactly; `save()`/`load()` take and return `ArtifactV1`. 0.x databases are refused.
- **`resolve` and `repl`** read `.json` or `.db` artifacts and ignore their old `--embedder` default; `--embedder` now only asserts the expected kind. `SerializedArtifact` is replaced by `ArtifactV1`.
- **Negative conformance fixtures** (`spec/artifact/fixtures/invalid/`): artifacts a loader must refuse — pre-1.0 and future format versions, a missing fingerprint, a tool id that is not `<providerId>/<name>`, an alias claiming `kind: "tool"`, a tool whose selector is an alias, a primary selector pointing at another tool, wrong vector dimensions, wrong `stats`, a tampered description — and seven fingerprints, each differing from the golden artifact's in one field, that must not be accepted for it. The TS suite runs them all.

#### Resolve/execute split, argument validation, one dispatch policy

- **Resolution and execution are separate.** `runtime.resolve(intent, { learn?, args? })` chooses at most one tool and executes nothing: it returns `{ outcome: 'resolved' | 'needs-disambiguation' | 'unresolved', tier, chosen?, confidence?, candidates, proof, reason?, refinement? }`, and with the default `learn: false` it neither interns the intent nor writes the cache. `runtime.dispatchById(toolId, args, { resolutionDigest? })` executes exactly the tool with canonical id `<providerId>/<toolName>` — an O(1) lookup with no embedding (`dispatchStreamById`, `getTool`, `toolIds` are new too). `runtime.dispatch(intent, args)` is resolve → policy → the same execution boundary. (SC-INF-14)
- **MCP `tools/call` names tools exactly.** It runs the tool whose listed name is given, via `dispatchById`, instead of a fuzzy semantic match that could run a different tool. (SC-INF-14; the exact-name half of SC-SURF-05. Names and unknown-name results are described under "`smallchat serve` rebuilt on the MCP SDK" below.)
- **One dispatch policy on every path** (`src/runtime/policy.ts`): pinned phrases, learned preferences, cache hits, vector and overload candidates, protocol conformance and decomposition sub-intents all pass `evaluateDispatchPolicy`. Destructive tools (MCP `destructiveHint: true`, or `readOnlyHint: false` without a `destructiveHint`) run only by exact id, a pinned phrase or EXACT similarity measured from the intent's own embedding — never from the cache or a learned preference — and are never cached. `treatUnannotatedAsDestructive` extends this to unannotated tools.
- **`requireLLMForSubHighDispatch` now defaults to `true`.** Below HIGH confidence a tool runs only when an LLM verifier (`LLMClient.microCheck`, now asked whenever its approval is what authorizes the call) approved it; otherwise the outcome is `needs-disambiguation`. When the LLM rejects the best candidate, alternates go through the same verification (LLM included) and the tier rules again, instead of being accepted on keyword overlap alone. (SC-INF-15)
- **Overloads are ranked with every other candidate.** An overloaded selector's matching signature becomes a candidate scored like any vector match, then sorted once and subjected to tiers, verification, strict mode and the policy; it no longer returns early ahead of better matches. A `SignatureValidationError` from an overload no longer escapes `dispatch()`: the selector is excluded and the violation is recorded in the proof. (SC-INF-05)
- **Intent pins cannot be bypassed.** `exact` pins match whole phrases after `normalizePinPhrase` (NFKC, case, whitespace) instead of `canonicalize()`, which dropped "not"; `IntentPinRegistry.checkExact()` and `checkSimilarity()` take the raw intent text. Pins are enforced on the cache, semantic-map (exact and similar) and protocol paths too, `elevated` pins are checked against the intent's own embedding (not an interned neighbour's vector), and pinned tools are never cached. A pin applies to every tool its selector dispatches to: overload variants of a pinned selector and every class that declares it, not only the selector's default tool. (SC-INF-04)
- **Arguments are validated against the tool's `inputSchema`** (Ajv; JSON Schema 2020-12 by default, 2019-09 and draft-07 by `$schema`) at the execution boundary and in `ToolProxy`. Compiled and artifact-loaded tools get `createSchemaConstraints()` (the 0.x constraints only checked that required keys were present, and the artifact loader accepted anything). Wrong types, out-of-enum values, unknown keys on closed schemas, `null`/`undefined` required values and inherited properties are rejected with one readable message per problem; the result is `isError: true` with `metadata.outcome: 'invalid-arguments'` and nothing runs. No type coercion unless `argumentCoercion: 'primitives'`. (SC-INF-11)
- **Dispatch results that ran nothing are errors.** An intent that does not resolve to one tool returns `isError: true` with `metadata.outcome` and the candidates' tool ids (refinement options carry `toolId`), instead of a success-shaped stub. The forwarding chain no longer executes anything: its superclass traversal (inherited selectors are now ranked like any other) and its 0.5-similarity "broadened search" auto-execution are gone. `DispatchContext.forward()`, `FallbackStep` and `FallbackChainResult` are removed. `UnrecognizedIntent` is deprecated: 1.0 never throws it (an unmatched intent is `metadata.outcome: 'unresolved'`); it stays exported for `instanceof` checks. Decomposition (LOW tier, or no match with an `LLMClient.decompose`) happens only when dispatching, is depth-bounded (see "Retrieval correctness and determinism"), and every sub-intent goes through the same pipeline and policy.
- **The resolution proof is structured and replayable** (`src/core/proof.ts`): `version`, `intent`, `outcome`, `decision` code, `tier`, `chosen`, `confidence`, `ran` (the tool that actually executed), `callDigest`, `resolutionDigest`, the full `candidates` table (score, own-embedding similarity, tier, source, exclusion reason), `thresholds`, `guards`, `embedder` fingerprint, `artifactHash`, `steps` (`{ stage, decision, detail? }` — never raw arguments), `timings` (performance.now) and `proofDigest` (SHA-256 over the canonical JSON of everything but timings). `resolvedTool`, `elapsed` and the steps' `input`/`output`/`elapsed` are gone; `createProof`/`addProofStep` moved from `core/confidence.ts` to `core/proof.ts` with new signatures. With arguments the cache is no longer consulted after vector search, so the proof can no longer name one winner while another tool runs. (SC-INF-16)
- **`DispatchBuilder.execContent()` throws `DispatchError` for an `isError` result** (an intent that ran nothing, or a tool that failed) instead of returning the error payload typed as the success value. `DispatchError` carries `outcome`, `candidates` (tool ids) and the full `result`. `DispatchOutcome` types `metadata.outcome`: `'resolved' | 'needs-disambiguation' | 'unresolved' | 'throttled' | 'invalid-arguments' | 'aborted' | 'not-dispatched'`.
- **Result metadata** adds `outcome`, `toolId` and `callDigest`; `topCandidates` entries are `{ toolId, confidence }` (were `{ tool, confidence }`). `DispatchEventToolStart` adds `toolId`.
- **`resolveRefinement()` runs the chosen tool by id** (and still reinforces the semantic map) instead of re-resolving the original intent. The learned preference records that tool id (`LearnedPreference.toolId`, serialized), so when the option was an overload variant or a second class on the same selector, the same intent later runs the tool the user picked, not the selector's default. Nothing is learned when the chosen selector does not dispatch to the chosen tool; `reinforceRefinement(intent, selectorId, toolId?)` throws in that case. A learned preference alone never authorizes a pinned or destructive tool.
- **`canonicalJson()` rejects non-plain objects** (`Date`, `Map`, class instances) instead of serializing them as `{}`.

#### Retrieval correctness and determinism

- **Intents are identified by their full text, not `canonicalize()`.** The resolution cache, the semantic map's exact fast path and explicit feedback key on `intentKey(text)`: Unicode NFC, trimmed, whitespace collapsed, lower-cased — nothing else removed. `canonicalize()` dropped stopwords such as "not" and every non-ASCII character, so "do not delete the logs" was served "delete the logs"'s cached destructive tool and every non-Latin intent shared the key `unknown`; it is now display-only (and keeps letters of every script). Intent selectors carry the key as `ToolSelector.key`. (SC-INF-03)
- **Runtime intents are never interned.** `SelectorTable` holds compiled tool and alias selectors only: `resolve(intent)` (and its alias `probe`) embeds the intent and changes nothing, so an intent can no longer inherit an earlier, similar intent's vector, crowd tools out of the candidate list, or swallow a tool registered later under the same canonical. `intern(embedding, canonical)` matches against tools only (the `provenance` parameter is gone); `RuntimeOptions.maxIntentEntries`, `all({ includeIntents })` and the `rateLimiter`/`maxIntentEntries` constructor parameters are removed. `searchTools()` skips index rows that are not registered selectors and widens its search until it has topK of them. (SC-INF-13)
- **Scores are quantized and ties are deterministic.** Every similarity is rounded to 1e-4 (`quantizeScore`) before it is ranked or compared with a threshold, and equal scores are ordered by canonical tool id (`compareRanked`) — in candidate ranking, in `searchTools()`'s topK cut, in `MemoryVectorIndex` and in the semantic map's similar-intent lookup. The rules and golden vectors are `spec/ranking/` (`smallchat.rank.v1`) for smallchat-swift parity. Determinism, precisely: the same artifact, embedder and runtime state (registered classes, pins, semantic map, feedback, cache, options) give the same outcome, candidate order and `proofDigest` for the same intent text; LLM verifier answers and an opted-in rate limiter's window are inputs, not covered.
- **`SqliteVectorIndex` uses cosine distance** (`distance_metric=cosine`). vec0's default was L2, which `search()` read as cosine distance: a 0.90-cosine match scored 0.553 and everything below ≈0.92 was filtered out, so `.db` artifacts and the embedding worker resolved differently from in-memory indexes. Opening a database whose `vec_selectors` table has no metric rebuilds it in place (ids and vectors kept); the SQLite artifact store now writes the cosine table. (SC-INF-02)
- **Registry changes take effect on the next dispatch.** `registerClass()` with the name of a registered class replaces it (re-indexed from scratch, so the old IMP is no longer reachable and its tool id is not ambiguous) and flushes cached resolutions; `unregisterClass(name)` is new; `swizzle()` flushes the whole cache (entries are keyed by intent, so the 0.x per-selector flush missed them) and swizzles the tool's alias selectors with it. `reinforceRefinement()` and `feedback()` flush the cache too. (SC-INF-07)
- **No implicit corrections by default.** `DispatchObserver` no longer treats a switch to another tool within 30 s as proof the first was wrong (search → open workflows blacklisted the search tool) and no longer turns caller-side argument errors into negative examples. Negative examples come from `runtime.feedback({ intent, toolId, correct, expectedToolId?, principal? })`; set `observerOptions.implicitCorrections: true` for the old inference. Negative examples are keyed by `(intentKey, toolId)` and may be scoped to a principal; `DispatchRecord.tool` is the canonical tool id. Adaptive thresholds were never applied and are removed (`getAdaptedThresholds`, `getAdaptiveThresholds`, `AdaptiveThreshold`, `correctionThreshold`, `thresholdBumpAmount`). (SC-INF-06, SC-INF-22)
- **The semantic rate limiter is opt-in and per principal.** A runtime has one only when `RuntimeOptions.rateLimiter` is set; windows are kept per `principal` (`resolve`/`dispatch` option, default `"default"`), only novel intents count (cache hits, pinned phrases and learned exact intents are never embedded), and the documented low-similarity heuristic is enforced. A throttled intent resolves to outcome `'throttled'` (decision `rate-limited`, `retryAfterMs`); nothing is thrown through dispatch. `ResolutionCache` no longer owns a limiter (`rateLimiter`, `checkFloodGate`, `recordIntent`, `getFloodingMetrics` removed; `SemanticRateLimiter.evaluate()` returns the typed verdict). `VectorFloodError` is deprecated and never thrown. (SC-INF-10)
- **Decomposition is bounded in depth and fan-out.** Default depth 2 (`maxDecompositionDepth`); sub-intents that restate the intent or one it was split from are dropped (a model that answers with the intent itself no longer recurses); at most `maxSubDispatches` (16) sub-intents run per request, the rest are reported as not dispatched. Depth and budget are per request, so concurrent dispatches never share them. (SC-INF-12, SC-INF-26)
- **Streaming dispatch runs every tool.** `ToolTransport.executeInference` is optional and used only when the transport's new `supportsInference(toolName)` says so; `ToolProxy` asks it before choosing token-level inference, so local, REST and gRPC tools stream through `executeStream`/`execute` instead of returning `""` without running. An inference stream that yields no deltas falls back to its returned `ToolResult` (a non-streamed upstream reply) or to `executeStream`/`execute`. (SC-INF-09)
- **Cancellation reaches the tool.** `ToolIMP.execute(args, { signal })` and `ToolTransport` methods take `ExecuteOptions`; `dispatch(intent, args, { signal, principal })`, `dispatchById(id, args, { signal })` and `dispatchStream(intent, args, { signal })` pass the signal on. `DispatchBuilder.withTimeout()` aborts the running tool when it fires (it only stopped waiting before), `withSignal()`/`withPrincipal()` are new, closing a dispatch stream early aborts the streaming tool, and a signal that fired before execution returns `metadata.outcome: 'aborted'` with nothing run. (SC-INF-26)
- **`WorkerVectorIndex` can back a runtime:** `search()` and `size()` return promises instead of throwing. (SC-INF-17)
- **Named-argument overload resolution** treats omitted optional parameters as satisfied, matches plain JSON objects and arrays against `SCData`/`SCArray` slots, prefers signatures that declare every provided name, and breaks ties exactly like positional resolution (arity, then developer-defined, else `OverloadAmbiguityError`) instead of keeping the first registered. (SC-INF-20)
- **ONNX embeddings are computed per text, unpadded.** The quantized model's dynamic activation quantization made a text's vector depend on padding and on the other texts in its batch (cosine ≈ 0.99 to its unpadded vector). Each text now runs alone at its own token length: `embed()` and `embedBatch()` agree exactly, and a short intent no longer pays for 128 positions. Vectors differ slightly from 0.x — recompile (1.0 refuses 0.x artifacts anyway). (SC-INF-21)
- **Dead knobs removed or wired.** `CompilerHint.priority` and `ProviderCompilerHints.priority` never affected dispatch and are removed (compile warns when a manifest still sets one); `preferred` is documented as the compile-time collision annotation it is. `CompilerOptions.strict` and `priorityHints` are removed. `ToolCompiler.compile(manifests, projectManifest)` now applies smallchat.json `compiler` thresholds (`duplicateThreshold`, `allowDuplicates`, `collisionThreshold`, `generateSemanticOverloads`, `semanticOverloadThreshold`) unless the constructor set them. The collision-zone hint no longer claims "MEDIUM-confidence verification"; the golden fixture `spec/artifact/fixtures/minimal.v1.json` is regenerated for the new text. (SC-INF-22)
- **Semantic map serialization is version 2** (`intentKey`, `exact`). `SemanticMap.fromJSON` still reads version 1, importing its entries for similar-intent boosts only, since their canonicalize() keys conflated distinct intents. `LearnedPreference.intentCanonical` is now `intentKey`.
- Hot path: no intent vectors in the tool index, and one vector search serves both the candidates and the refinement options. Cache hits never embed.

#### `smallchat serve` rebuilt on the MCP SDK as an exact aggregator

- **`serve` runs on the official MCP SDK (`@modelcontextprotocol/sdk`, now a dependency) and executes tools.** It forwards every `tools/call` to the upstream MCP server that owns the tool, through SDK clients (`UpstreamPool`) started or reached from the artifact's provider launch specs: stdio servers are spawned with the SDK's safe default environment plus the variables the spec names, read from serve's own environment (artifacts hold names, never values); Streamable HTTP and legacy SSE servers are reached at their URL. Clients connect lazily, reconnect after an upstream exits, and receive the downstream client's cancellation and progress. `loadRuntime()` wires the same pool into every runtime it builds and returns it as `upstreams` (close it when done), so `runtime.dispatchById()` executes MCP tools in library use too. Previously no compiled tool could run: every call failed with "No MCP endpoint configured". (SC-SURF-01)
- **Tool names are provider-qualified and collision-free.** Aggregate mode lists `<providerId>__<toolName>` (always `^[A-Za-z0-9_-]{1,128}$`); a provider id prefixes names only if it has no `__` and does not end in `_`, so each name maps back to exactly one tool. Tools whose names cannot be represented are left out with a startup message and never renamed. `serve --provider <id>` serves one provider under its upstream names, verbatim, so OpenAPPA batteries keyed `mcp/<server>/<tool>` apply unchanged. Each tool carries its upstream `title`, `description`, `inputSchema`, `outputSchema` and `annotations`. `buildToolList(artifact, { provider? })` returns these names. (SC-SURF-07, serve side)
- **`tools/call` is exact-name only; unknown names are `isError` results.** Canonical ids (`github/create_issue`), bare upstream names in aggregate mode and natural-language phrases are not tool names. They return an `isError` result that lists close names and never execute anything (this replaces the `-32602` error added earlier in this release). (SC-SURF-05)
- **Semantic resolution is the `smallchat_resolve` tool.** `{ intent, args? }` returns the `runtime.resolve()` proposal (`outcome`, `toolId`, the MCP `name`, `tier`, `confidence`, ranked `candidates`, `proofDigest`, and `retryAfterMs` when a `runtimeOptions.rateLimiter` answers `throttled`) as `structuredContent` and never executes. Its `outputSchema` lists all four outcomes, so spec clients accept a throttled proposal. It is read-only (`readOnlyHint`, `idempotentHint`). Turn it off with `--no-resolve-tool` / `resolveTool: false`.
- **Results pass through, carry their reason and a proof.** Upstream results keep every content block (image, audio, resource links, embedded resources), `structuredContent` and `isError`. Failures carry their reason as text, including each argument violation. The non-spec top-level fields `confidence`, `refinement` and `rtkSavedPct` are gone. Every result carries `_meta["dev.smallchat/resolution"]` = `{ toolId, ran, outcome, decision, tier, callDigest, proofDigest, artifactHash }`. RTK savings move to `_meta["dev.smallchat/rtk"]`. `formatContent` is replaced by `toCallToolResult`. (SC-SURF-19)
- **stdio by default; Streamable HTTP only with `--http`, guarded.** The single endpoint is `/mcp` (POST, GET for the server stream, DELETE to end a session), with SDK-negotiated protocol versions (2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05, 2024-10-07). Notifications get 202, and unknown sessions get 404. Before MCP sees a request: the Host must be an allowed hostname (loopback names by default; a wildcard bind requires `--allowed-host`), an Origin must be explicitly allowed (`--allowed-origin`; none by default), and a bearer token is required, including for `initialize`. The token is generated into `~/.smallchat/serve-token` (mode 0600; `--token-file`), and `--http-insecure` opts out. Bodies must be `application/json` (415), at most `--max-body-bytes` (413) and a JSON-RPC message or batch (400). Sessions are capped (`--max-sessions`) and expire when idle (`--session-idle-timeout`). `null`, non-object and invalid JSON bodies, oversized bodies and clients that disconnect mid-body get error responses or are dropped; they no longer crash the process. In stdio mode all logging goes to stderr. (SC-SURF-04, SC-SURF-08, SC-SURF-09)
- **Removed:** `POST /` and `/rpc`, `GET /sse`, `GET /.well-known/mcp.json`, `GET /health`, the non-standard `shutdown` method, SSE streaming of `tools/call` via `Accept` on the old endpoint, the built-in OAuth token endpoint (`POST /oauth/token`) and `OAuthManager`/`MCP_SCOPES`, SQLite session persistence (`SessionStore`, `--db-path`, `--session-ttl`), and the `--auth`, `--audit` and `--cors-origin` flags (replaced by the bearer token, `--audit-log <file>` and `--allowed-origin`). The OAuth layer never had registered clients from the CLI, never enforced scopes and exempted `initialize` from auth. Acting as an OAuth 2.1 resource server (RFC 9728 metadata, tokens from an external authorization server) is future work. (SC-SURF-12)
- **Unknown tool names are bounded work.** A `tools/call` name longer than 128 characters (`MAX_TOOL_NAME_LENGTH`) gets no "close names" suggestions, edit distances are computed only where the lengths allow a match, and the name is shortened (`displayToolName`) in the error text and the audit entry. Before, a multi-megabyte name kept the event loop busy for minutes and was stored whole in every audit entry.
- **Programmatic tools get their arguments validated.** `registerTool` / `registerApp` executors run only after the arguments pass the tool's `inputSchema` (same validator and `argumentCoercion` as artifact tools); otherwise the call is an `isError` result listing each violation, and a schema that does not compile refuses every call. Before, executors received raw arguments although the docs said otherwise.
- **`MCPServer` API:** `new MCPServer({ sourcePath?, provider?, resolveTool?, upstream?, runtimeOptions?, rtkConfig?, auditLog?, log? })`; `startStdio()` / `closed()`, `startHttp(options)` → `{ url }`, `createHttpHandler(options)` (after `load()`), `stop()`, `listTools()`, `toolTable`. `start()`, the `port`/`host`/`dbPath`/`enableAuth`/`enableRateLimit`/`enableAudit`/`sessionTTLMs`/`corsOrigin`/`maxBodyBytes` config fields and the `oauth` getter are gone. `McpTool` is the MCP Tool shape (`name`, `title?`, `description?`, `inputSchema`, `outputSchema?`, `annotations?`, `_meta?`); its invented `id`, `tags` and `version` are removed. `registerTool` refuses names already served.
- **Unused "MCP 2025-11-25" router stack deleted.** `McpRouter`, `SessionManager`, `SseBroker`, `ToolRegistry`/`ResourceRegistry`/`PromptRegistry` in `registry.ts`, `wire-format.ts`, `transports/http.ts`/`stdio.ts`, `MCP_ERROR` and the router types are removed. Nothing served them, and their wire format was invented. `MCP_PROTOCOL_VERSIONS` is now exactly the SDK's supported list (it claimed `['2025-11-25']` while the server spoke 2024-11-05). The router-based `scripts/test-mcp-server.ts` benchmark harness and its helpers are removed. Router tests are replaced by SDK-client conformance tests against the real server. (SC-SURF-24)
- **Audit log records real outcomes.** One entry per JSON-RPC request after its response is sent: `outcome` (`ok` / `error` / `rejected`), `errorCode`, `httpStatus`, `remoteAddress`, `requestId`, and for `tools/call` the `toolName` called, the `toolId` that ran and its `callDigest`, never arguments. HTTP rejections (Host, Origin, token, rate limit, content type, body size, malformed JSON, unknown session, client disconnect) are recorded too. `AuditEntry.success` and `clientId` are replaced. `new AuditLog({ file })` / `--audit-log <file>` appends JSON lines (mode 0600; not hash-chained). (SC-SURF-27)
- **`serve --decision-log <file>`** appends every `tools/call` (`dispatch-by-id`, with the call digest of what ran, or `invalid-arguments` / `aborted`) and every `smallchat_resolve` to the hash-chained decision log before anything runs; `smallchat replay <artifact> <log>` reproduces it. `MCPServer.stop()` closes a log the runtime opened from a path (a `DecisionLog` instance passed in stays open). The request's cancellation signal reaches `dispatchById`, so a call cancelled before it starts runs nothing.
- **Upstream MCP calls honour `ExecuteOptions.signal`.** `UpstreamPool.callTool(providerId, toolName, args, { signal? })` and the pool's tool transport cancel the upstream request (`notifications/cancelled`) when the caller's signal fires, so `dispatchById(id, args, { signal })` and `DispatchBuilder.withTimeout()` on a `loadRuntime()` runtime stop the upstream tool, not only serve's own requests. The transport's no-op `executeInference` is gone (it is optional since the streaming fix above).
- **Resource subscriptions belong to the session that made them.** `resources/subscribe` / `unsubscribe` take `{ uri }` per the spec (no subscription ids), are idempotent per session, notify only that session, and are released when the session closes. (SC-SURF-29)
- **`doctor --mcp` runs real conformance checks** (`runConformance`, shared with the test suite): the SDK client connects over stdio (`--mcp-source <artifact>` spawns `serve`) or HTTP (`--mcp <url>`, token from `--token-file`), checks the negotiated protocol version, `ping`, `tools/list` (unique valid names, object input schemas), that an unknown tool is refused, `smallchat_resolve`, an optional end-to-end `--mcp-call`, and over HTTP a notification (202) plus the Host/Origin/token/content-type/null-body/unknown-session refusals. Every step has a timeout. The old check passed `tools/call` in both branches and counted an aborted SSE fetch as a pass. (SC-SURF-22)
- **`smallchat resolve` uses the runtime's resolution, and `--execute` needs HIGH tier or `--force`.** It loads the artifact with `loadRuntime` and the `smallchat.json` policy, prints `runtime.resolve()`'s outcome, candidate table and proof digest, and with `--execute` runs the chosen tool via `dispatchById` on its upstream server, only at EXACT/HIGH tier unless `--force`. It previously searched the vector index directly at ≥ 50% similarity and executed the top hit. `--endpoint` is removed (the launch spec decides); `--json` and `--decision-log` are new. The old "✓ Unambiguous" / "? Ambiguous" lines, derived from a 90%-similarity rule the runtime never applied, are gone. (SC-SURF-23)

#### `smallchat doctor` checks the project's artifact

- **`smallchat doctor` exits 1 when the project's artifact fails a check.** With `--artifact <path>`, or `./tools.toolkit.json` when present, doctor now verifies artifact ↔ embedder ↔ index compatibility (see Added, "Replay, explain and a decision log"). A pre-1.0, tampered or unloadable artifact used to pass doctor; it now fails it.

#### Outbound MCP clients on the SDK

- **Every outbound MCP connection uses the official SDK client** (`src/transport/mcp-connect.ts`): config introspection, `McpStdioTransport`, `McpHttpTransport`, `MCPTransport` and serve's `UpstreamPool`. They complete the initialize handshake (with `notifications/initialized`), negotiate the protocol version, send the `Accept`, `Mcp-Session-Id` and `MCP-Protocol-Version` headers, keep the session, and time out every request. A timeout or abort cancels the request upstream with `notifications/cancelled`. `McpSseTransport` and `MCPTransport` used to POST a bare `tools/call`, which every spec server answers with `406 Not Acceptable`, and `MCPTransport` had no timeout at all. (SC-SURF-13)
- **`McpSseTransport` is now `McpHttpTransport`** (`type: 'mcp-http'`). It speaks Streamable HTTP, legacy HTTP+SSE, or `transport: 'auto'` (the default: Streamable HTTP first, then SSE if the server answers with a 4xx). Its `auth` strategy is applied to every request, so refreshed tokens are used. `McpSseTransport` stays as a deprecated alias with the same behaviour, and its `reconnectDelayMs` is ignored. `executeStream` yields the single final result, because the SDK handles the SSE framing. `MCPTransport` gains `timeoutMs` (default 60 s, which also applies to REST calls) and `close()`. `clearTransports()` closes open sessions. The MCP `executeInference` no longer yields anything: the `X-MCP-Stream-Mode: inference` request it used to send is not part of MCP.
- **Config introspection handles remote servers, and one bad entry no longer aborts the scan.** Entries with `type: "http"`, `"streamable-http"` or `"sse"`, and bare `url` entries, are introspected over HTTP, with their `headers`. The manifest's launch spec records the URL and the transport that worked. An entry is reported and skipped, while the rest still compile, when it has an unknown `type` (e.g. `ws`), no `command` or `url`, malformed `args`/`env`/`headers`, or an unset `${VAR}`, or when its server fails. Before, a single remote entry made the whole scan throw `The "file" argument must be of type string`. `tools/list` is now read to its last page (before, only the first page was read). `${VAR}` and `${VAR:-default}` are expanded in `command`, `args`, `env`, `cwd`, `url` and `headers` the way Claude Code expands them. Launch specs keep the unexpanded templates, and serve expands them from its own environment, so no expanded value is written to the artifact. `McpServerConfig` is now `McpStdioServerConfig | McpRemoteServerConfig`. `introspectMcpConfigFile` takes `{ timeoutMs, env, log, exclude, forwardProxyEnv }`, and the new `introspectMcpServers(servers, options)` introspects an `mcpServers` object. Error messages include the end of the server's stderr. (SC-SURF-14)
- **`McpStdioTransport` drains stderr, restarts after a failure and cleans up its process.** It reads the server's stderr continuously into a bounded tail (`stderrTail()`), so a server that logs heavily can no longer fill the pipe and hang. A failed start is not cached any more: the next call starts the server again after a backoff (`restartBackoffMs`, default 1 s, doubling up to 30 s). A start that fails or times out stops the process, and `dispose()` ends it (closes stdin, then SIGTERM, then SIGKILL). A call that times out is cancelled upstream and dropped, and the transport stays usable. `listTools()` returns every page. New config fields are `timeoutMs`, `restartBackoffMs`, `inheritEnv` and `forwardProxyEnv`, plus a `pid` getter. stdio servers are spawned through the SDK, which uses cross-spawn, so `npx` and other `.cmd` shims now resolve on Windows. (SC-SURF-15)
- **The container sandbox keeps environment values off the docker command line, and the environment allowlist depends on the platform.** `buildDockerArgs` emits only `-e NAME`. The values reach docker through its process environment (`buildMcpSpawnSpec`), so tokens can no longer be read from `ps` or `/proc/<pid>/cmdline`. The docker client now gets the safe environment, `DOCKER_HOST`/`DOCKER_CONTEXT`/`DOCKER_CONFIG`/`DOCKER_CERT_PATH`/`DOCKER_TLS_VERIFY` and the server's own variables, instead of the whole parent environment. `safeInheritedEnv()` returns the platform's allowlist. On Windows that now includes `SYSTEMROOT`, `APPDATA`, `LOCALAPPDATA`, `USERPROFILE`, `TEMP`/`TMP`, `PATHEXT`, `ComSpec` and the rest of what `npx` needs. Proxy and CA variables (`HTTP(S)_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, …) are forwarded only with `forwardProxyEnv: true` or `SMALLCHAT_FORWARD_PROXY_ENV=1`, because proxy URLs can carry credentials. `spawnMcpProcess` is kept, but the SDK-based clients are preferred because they drain stderr. (SC-SURF-20)

#### `HttpTransport` retries only idempotent calls; streamed uploads are sent whole

- **Retries no longer repeat side effects.** With a `retry` config, `HttpTransport` retries only idempotent methods (GET, HEAD, PUT, DELETE, OPTIONS) and requests that already carry an `Idempotency-Key`. A POST or PATCH is sent once unless `retry.retryNonIdempotent: true`. When it is set, each logical call gets one generated `Idempotency-Key` (`retry.idempotencyKeyHeader` to rename it), sent on every attempt. Before, a POST that timed out was sent up to `maxRetries + 1` times while the caller was told it failed: the audit saw `create_payment` run four times. Retries follow `retry.retryableStatuses`, which used to be ignored. (SC-SURF-18)
- **The circuit breaker counts 5xx responses** whether or not `retry` is configured. Before, without `retry`, a server answering 500 never tripped it. A failed response keeps its parsed body in `content` (with `isError: true`, `statusCode`, `code` and `error` in metadata), including after retries run out. Before, `content` became `null` in that case.
- **Token acquisition runs inside the request timeout**, so a hung token endpoint can no longer hang the call. `OAuth2ClientCredentialsAuth` makes one token request for concurrent callers (single flight).
- **ReadableStream uploads are sent whole.** `HttpTransport` reads each streamed `FileUpload` into memory before building the multipart body. The cap is `maxUploadBytes` (default 50 MiB), and a larger stream fails the call instead of being cut short. `buildMultipartBody` now throws for a stream rather than appending an empty file. Before, the remote received a 0-byte file while the call reported success. `bufferFileUploads()` is exported. (SC-SURF-26)

#### Channel HTTP bridge: mandatory credentials, identity from the credential

- **`--http-bridge` requires a credential and refuses to start without one.** The shared secret comes from `$SMALLCHAT_CHANNEL_SECRET` or `--http-bridge-secret-file <path>`, a file other users cannot read, with at least 16 characters. Per-sender tokens come from `--http-bridge-tokens-file <path>` (`{"<identity>": "<token>"}`). `--http-bridge-secret <token>` is rejected with a pointer to those: secrets on the command line are visible in `ps` and end up in committed `.mcp.json` files. `ChannelServer.start()` throws when `httpBridge` is set and neither `httpBridgeSecret` nor `httpBridgeTokens` is. Credentials are compared in constant time over SHA-256 digests, and the bridge refuses two identities that share a token. The wire contract is unchanged: `POST /event` with `X-Channel-Secret` or `Authorization: Bearer`. (SC-SURF-10)
- **The sender is the credential's identity, not a body field.** The shared secret authenticates as `httpBridgeSecretIdentity` (`--http-bridge-secret-identity`, default `bridge`), and each per-sender token as its own identity. The sender allowlist is checked against that identity. Body `sender` and `channel` fields are ignored. Events carry the configured channel name, so a poster can no longer pick another channel's provenance. Bodies in the `{channel, content, sender, meta}` shape that stenographer sends are still accepted. (SC-SURF-10)
- **Permission verdicts need an authenticated approver.** `POST /permission` is accepted only from identities in `permissionApprovers` (`--permission-approvers`). With no approvers configured, every verdict is refused, whereas before anyone who could reach the port could approve a pending `Bash` call. The `permission-verdict` event carries `approver`, and the CLI logs it. `sendPermissionVerdict(verdict, approver?)` records who decided programmatically. The notification sent to Claude Code is unchanged. (SC-SURF-10)
- **Requests are checked before anything reaches Claude Code.** The Host header must be a loopback name for a loopback bind (DNS rebinding; `--http-bridge-allowed-host` or `httpBridgeAllowedHosts`, which a wildcard bind requires). A request with an `Origin` must match `httpBridgeCorsOrigin`. POST bodies must be `application/json` (415 otherwise, which blocks cross-site `text/plain` posts). Every endpoint except `/health` needs the credential. (SC-SURF-10)
- **Malformed and oversized requests no longer crash the channel.** A `null`, array or non-JSON body gets 400, a non-object `meta` gets 400, a body over `httpBridgeMaxBodyBytes` (default 256 KiB) gets 413, and content over `maxPayloadSize` gets 413. Handler errors are answered (500 at worst) and never become unhandled rejections. Before, a `null` body or a 300 KB body killed the subprocess and Claude Code lost the channel. `httpBridgePort: 0` and the `httpBridgeAddress` getter allow ephemeral ports. (SC-SURF-11)
- **`meta.source` is reserved.** `filterMetaKeys` and `isValidMetaKey` drop `source`, so `serializeChannelTag` emits one `source` attribute: the channel name. Before, `meta.source` produced a second, forged `source="..."`. `RESERVED_META_KEYS` is exported. (SC-SURF-25)
- **Claude Code sees who posted.** The `notifications/claude/channel` notification carries `meta.sender` = the event's sender, which for bridge events is the authenticated identity. `sender` and `user` join `RESERVED_META_KEYS`, so a body can no longer present another identity in the `<channel>` tag (before, bob's token could post `meta: {sender: "alice"}` and nothing identified bob). `ChannelEvent.meta` stays what the body sent (filtered); the identity is `ChannelEvent.sender`. `serializeChannelTag(channel, content, meta?, sender?)` takes the sender as an argument and never from meta.
- **`GET /sse` streams permission requests to approvers only.** Every authenticated identity still receives channel events and replies (the channel's traffic); `permission-request` events, which carry the pending tool call, go only to identities in `permissionApprovers`. Before, any credential holder could watch pending approvals.
- The webhook example passes the secret through the environment (`"${SMALLCHAT_CHANNEL_SECRET}"`) and launches `npx -y @smallchat/core`. (SC-SURF-31)

#### `setup` adds smallchat next to your servers; `rtk setup`, `init` and `compile` fixed

- **`smallchat setup` never replaces `mcpServers`.** It adds a `smallchat` entry next to the existing servers. With `--disable-originals`, or a "yes" to the new prompt, the other servers move verbatim under `smallchatDisabledMcpServers` in the same object, so they are kept and can be restored. Before, setup replaced the whole `mcpServers` object with a single entry, and every previously working server disappeared from the config. Later runs compile from the live servers plus the set-aside ones, and never from smallchat's own entry. (SC-SURF-02)
- **Backups are timestamped and never overwritten**: `<config>.smallchat-backup-<ISO timestamp>[-n]`, written exclusively (`wx`) with the config's own file mode. Before, `<config>.backup` was overwritten on every run, so a second run destroyed the only copy of the original config. The config is rewritten atomically and keeps its mode, and a config that is not valid JSON is left untouched. (SC-SURF-02)
- **The entry speaks the right transport through the right package.** It is `{"type": "stdio", "command": "npx", "args": ["-y", "@smallchat/core@<this version>", "serve", "--source", "<abs toolkit>"]}`, or with `--launcher node` this installation's CLI by absolute path (refused from the npx cache). Before, the entry ran the unscoped `smallchat` package's `serve` through `npx`, against an HTTP-only server. The unscoped `smallchat` npm name is unregistered, so anyone could publish it, and `npx` installs without asking when stdin is not a TTY, which is how MCP hosts start servers. Before anything is written, setup starts the compiled toolkit with this installation's CLI over stdio, completes `initialize` and lists the tools (`--no-verify` skips this). (SC-SURF-02, SC-SURF-03)
- New `setup` options: `--config <path>`, `--output <path>`, `--embedder onnx|hash`, `--install` (non-interactive config update), `--disable-originals`, `--launcher npx|node`, `--no-verify`. Exported helpers: `installSmallchatEntry`, `smallchatServerEntry`, `serversToCompile`, `verifyServeEntry`.
- **`smallchat rtk setup` no longer damages `.claude/settings.json`.** A settings file that is not valid JSON (e.g. a trailing comma) now stops setup with an error, and the file is left byte-for-byte unchanged. Before, it was replaced with only `{hooks}`, which silently deleted `permissions.deny` and `env`. `.claude/` is created if missing (it used to crash with ENOENT). Every existing key is kept, the file is written atomically, and the hook is registered once. (SC-SURF-16)
- **The installed hook works.** It is a script, `.claude/hooks/smallchat-rtk-rewrite.mjs`, run as `node "${CLAUDE_PROJECT_DIR}/.claude/hooks/smallchat-rtk-rewrite.mjs"`. It sets no `permissionDecision`, so Claude Code's permission rules still apply, to the rewritten command. The old inline `node -e` hook was a SyntaxError on every Bash call, and it echoed the raw input; setup now replaces it. (SC-SURF-16)
- **RTK filtering survives an rtk that exits early.** `filterContentWithRtk` / `RtkTransport` listen for stdin errors, so an EPIPE no longer crashes the process. In every failure case the original content is returned (before, a 4 MB tool result piped to an rtk without the `filter` subcommand crashed `serve --rtk`, or came back empty). (SC-SURF-17)
- **`smallchat init --no-git` / `--no-install` work.** `init` now runs `git init` (unless the directory is already inside a work tree) and `npm install`, and the flags skip them. Before, both flags were no-ops and neither step ever ran. The basic template registers its sample tools and compiles `./manifests` with `loadRuntime`. It resolves an intent and runs the chosen tool with `dispatchById`. Before, it dispatched against an empty runtime. The generated `package.json` depends on `@smallchat/core@^<this version>` and gains `start` and `doctor` scripts. The printed next steps use `npm run compile` / `npm run doctor`, never an unscoped `npx` name. (SC-SURF-31)
- **`smallchat compile` loads each manifest file once.** A file reached through `--source` (or auto-detection) and again through smallchat.json `manifests` or local `dependencies` is compiled once; every `init` project lists `./manifests` there, so `npm run compile` failed with "Tool id … is declared more than once" now that the compiler refuses duplicate tool ids. Manifest discovery skips `node_modules` and dot-directories. The `init` smallchat.json writes `compiler.duplicateThreshold` (the deprecated `deduplicationThreshold` is still read).
- **The quickstart and examples run on 1.0.** The basic template resolves an intent that reaches HIGH with the default embedder, so `npm start` runs the tool. QUICKSTART shows the outputs `resolve` actually prints (a HIGH match and a needs-disambiguation one), registers the local handlers, and uses `resolve` → `dispatchById`, `execContent()` and `DispatchError`. #### Satellites: Next.js, React, playground, dream

- **`@smallchat/nextjs` handlers require authorization.** `createDispatchHandler`, `createStreamHandler` and `createToolListHandler` throw at construction unless given `authorize(request, call)` or an explicit `unsafePublic: true`. `authorize` runs before the runtime does any work and returns `true`, `false` (403) or a `Response` to send as-is; `call` is `{ kind: 'dispatch' | 'stream', intent, args }` or `{ kind: 'list' }`. Bodies over `maxBodyBytes` (default 64 KiB) get 413, `args` must be an object, thrown errors reach `onError` (default `console.error`) and the response says only "Dispatch failed.", and the request's signal cancels the dispatch. A runtime built with `requireLLMForSubHighDispatch: false` is refused (500) unless `allowSubHighDispatch: true`, so below-HIGH intents come back as `needs-disambiguation`. `createToolListHandler`'s `GET` takes the request. The documented `export const POST = createDispatchHandler();` served a public route that resolved and ran any intent for anyone. (SAT-25)
- **`@smallchat/react` runs one stream at a time.** Calling `stream()` / `infer()` again, `cancel()` or unmounting aborts the previous run through the runtime's `signal` (the running tool is cancelled) and drops its events; `useToolDispatch` and `useAppDispatch` keep only the latest call's result. Before, a shared cancel flag was reset on every call, so two streams appended to the same state, and a slower earlier dispatch overwrote a later result. (SAT-27)
- **`AppView` hosts MCP Apps views.** It is the host side of the MCP Apps protocol (`@modelcontextprotocol/ext-apps`, now a dependency of `@smallchat/react`): an `AppBridge` answers the view's JSON-RPC `ui/initialize`, then sends `ui/notifications/tool-input` (the new `toolInput` prop) and a `ui/notifications/tool-result` (a `CallToolResult`) for the current `toolResult` and every later one, answers the view's `tools/call` with the new `onCallTool(name, args)`, and reports tool calls and `ui/message` through `onInteraction`. A `ui://` `componentUri` is an MCP resource, not a URL: pass its HTML as `html`, or `readResource(uri)` to read it (an alert explains what is missing otherwise); it renders through `srcdoc`. An `http(s)` view is loaded as `src`. The default `sandbox` is `allow-scripts` without `allow-same-origin`, which gives the frame an opaque origin: messages are posted to `'*'` and accepted only from the frame's own window, and with `allow-same-origin` they are also bound to the frame's origin. The bridge lives as long as the frame's content, so every new `toolResult` reaches an initialized view (before, a new `toolResult` object or an inline `onInteraction` re-ran the mount effect, reset readiness and dropped later results). `ref.current.teardown()` sends `ui/resource-teardown` and resolves once the view answers: await it before unmounting, because a frame that has been removed receives nothing. Before, `AppView` spoke a private `{ type: 'mcp-ui/ready' }` protocol that no ext-apps view sends, posted to the view URL's origin (which a sandboxed frame's opaque origin never matches, so `http(s)` views received nothing) and posted its teardown after the frame was gone. A Chromium test runs a real ext-apps view in both sandbox modes. `AppView` is a `forwardRef` component, and its declarations no longer name the global `JSX` namespace, which `@types/react` 19 removed (`npm run test:pack` typechecks them against React 19's types). New props: `html`, `readResource`, `toolInput`, `onCallTool`, `onError`. (SAT-26)
- **`@smallchat/playground` resolves through the runtime.** It loads the artifact with `loadRuntime` and shows `runtime.resolve()`'s outcome, tier, chosen tool id, candidates and proof digest; `/api/resolve` returns those fields (`resolvedSelector` and `matches` are gone), `/api/tools` lists canonical tool ids, and it listens on 127.0.0.1. It reported the typed intent's own canonical as the "resolved selector" at 100% with provider "unknown". `createPlaygroundServer(toolkitPath)` is exported. The package is `private`: it runs from source and is not published. (SAT-15)
- **`smallchat dream` never removes a tool on heuristics.** Strong negative memory signals become `ToolPriorityHints.proposedExclusions`, listed in the report for a person to confirm; only an explicit `exclude` list (`smallchat.dream.json`, `--exclude <tools...>`) removes tools, plus the proposals with `applyProposedExclusions` / `--apply-proposed-exclusions`. A call counts as failed only when the harness's `is_error` says so (reading outputs for "error" marked successful source reads as failures), and memory sentiment is read from the clause that names the tool ("use X instead of Y" is positive for X, negative for Y). Before, "Use read_file instead of cat" plus "Avoid raw shell reads; read_file is safer" excluded `read_file` from compilation. (SAT-22)

#### Replay, explain and a decision log (exact by construction, checkable)

- **`smallchat replay <artifact> <traces…>`** runs golden dispatch traces — JSONL or JSON cases `{intent, args?, expect: {toolId, tier?} | {outcome: "needs-disambiguation", candidates?} | {outcome: "unresolved"}}` — through `runtime.resolve()` with learning, cache and semantic map frozen (nothing executes or is learned; case order cannot change a result). Exit 0 pass, 1 mismatch, 2 could not run; `--json`, `--config <smallchat.json>` (default: the nearest one, as serve), `--semantic-map <file>` (learned state, read-only). Library: `parseTraceFile`, `loadTraceFiles`, `replayTraces`, `replayPaths`, `checkExpectation`, `formatReplayReport`.
- **Golden traces for the example manifests** in `examples/traces/` (36 cases over the 33 `examples/*-manifest.json`, including the bare name `create_issue` shared by github, gitlab and linear, which must stay needs-disambiguation). `npm run test:traces` compiles the examples with the default ONNX embedder and replays them; CI runs it after the build.
- **Durable decision log** (`RuntimeOptions.decisionLog`: a path, `DecisionLogOptions` or a `DecisionLog`; `serve --decision-log`, `resolve --decision-log`, `explain --decision-log`). One append-only JSONL line per `resolve()`, intent dispatch (streaming included, and each decomposition sub-intent) and dispatch by id: `{schema: "smallchat.decision.v1", seq, ts, kind, intent?, intentDigest, principal, artifactHash, embedderFingerprint, outcome, decision, tier, toolId, execution, callDigest, proofDigest, prevHash, hash}`, hash-chained like the suite's truth format (`hash` = SHA-256 of the JCS of the line without `hash`; `prevHash` null on seq 1). Raw arguments are never recorded; `recordIntent: false` keeps only `intentDigest` (`sha256(UTF8("smallchat.intent.v1") || 0x00 || UTF8(JCS(intent)))`). A dispatch's line is written before the tool runs, and a write failure throws `DecisionLogError` with nothing run. Reopening a log continues its chain after checking its last line. `verifyDecisionLog()` reports the first edited, removed, reordered or inserted line; `replayDecisionLog(runtime, records)` re-resolves the logged intents and reports, per line, reproduced / differs / skipped (other artifact or embedder, digest-only, LLM-verified, decomposed, throttled). `smallchat replay` recognises decision logs among its inputs and verifies, then replays them. Tested: replaying a log of mixed outcomes against the same artifact reproduces every outcome, tool id and tier, and every `resolve` line's `proofDigest`.
- **`smallchat explain <artifact> <intent>`** and `runtime.explain(intent, { args?, principal? })`: thresholds and guards in force, outcome, decision and reason, and the candidate table — rank, score, own-embedding similarity, tier, source, MCP hints (read-only / destructive / pinned), the dispatch policy's verdict on running each candidate without the caller naming it, and exclusions — plus the proof's steps and `proofDigest`. `--json` for machines.
- **`smallchat doctor --artifact <path>`** (`diagnoseArtifact()`): the artifact reads and its content hash verifies; its embedder can be built here; every vector has the fingerprint's dimensions (and unit length when normalized); re-embedding each tool's selector text reproduces the stored vector (cosine ≥ 0.999; most selectors drifting fails, a few warns); the vector index — the sqlite-vec table, opened read-only, for `.db` artifacts — holds exactly the artifact's selectors with the cosine metric and each finds itself first; distinct tools at cosine ≥ 0.90 (`findNearDuplicates`) and tool names shared by several providers are reported.
- `toolEmbeddingText(name, description, selectorHint?)` is exported from the compiler (the text a tool's primary selector embeds). `DispatchByIdOptions.principal` is recorded in the decision log.

### Security

- **`serve` over HTTP is guarded before MCP sees a request**: stdio is the default; `--http` requires an allowed Host (loopback by default), an explicitly allowed Origin and a bearer token (generated, mode 0600), including for `initialize`; JSON content type, a body limit, session caps and idle expiry apply, and malformed bodies cannot crash the process. The OAuth layer, which never enforced scopes and exempted `initialize`, is removed. (SC-SURF-04, SC-SURF-08, SC-SURF-09, SC-SURF-12)
- **The channel HTTP bridge requires a credential** (never on argv), takes the sender from it, lets only configured approvers answer permission requests, streams those requests only to approvers, checks Host, Origin and content type, XML-escapes channel content and reserves `source`, `sender` and `user` meta keys. (SC-SURF-10, SC-SURF-11, SC-SURF-25)
- **No unscoped npm names.** `setup` writes `npx -y @smallchat/core@<version>` (or this installation's CLI by path), `init` prints `npm run` scripts, and the docs use the scoped package; the unscoped `smallchat` name is unregistered and `npx` installs without asking when an MCP host starts it. (SC-SURF-03, XSUITE-07)
- **Secrets stay off command lines and out of artifacts.** Artifacts record environment variable names, never values; the container sandbox passes values through docker's environment, not `-e NAME=value`; spawned MCP servers get a platform allowlist of the parent environment plus their declared variables, and proxy variables only on request. (SC-SURF-20)
- **Side effects are not repeated.** `HttpTransport` retries only idempotent requests, or POSTs with one `Idempotency-Key` per logical call when opted in. (SC-SURF-18)
- **Web satellites fail closed.** `@smallchat/nextjs` handlers need `authorize` or an explicit `unsafePublic: true` (SAT-25); `AppView` no longer grants `allow-same-origin` by default, accepts messages only from its own frame, and binds them to the frame's origin when the sandbox gives it one (SAT-26).
- **Parsing.** Manifests, configs and artifacts are parsed with `safeJsonParse` (rejects `__proto__`, `prototype` and `constructor` keys); `SCDictionary.unwrap()` builds a null-prototype object; local manifest dependencies that escape the config directory are skipped; the playground HTML-escapes every value from a toolkit.
- `.gitignore` covers common secret files (`.env*`, `*.key`, `*.pem`, …) and SQLite write-ahead files.
- `vitest` `^3.2.7` (GHSA-5xrq-8626-4rwp). `npm audit fix` applied at the root and in `packages/docs` (Docusaurus 3.10.2). Accepted risk: `adm-zip` < 0.6.0 via `onnxruntime-node`'s install-time script, which only unpacks its own npm-hosted binary.

## [0.4.0] - 2026-04-01

### Added
- **Confidence-tiered dispatch (Pillar 1)** — Every dispatch returns a confidence tier (EXACT/HIGH/MEDIUM/LOW/NONE) that determines runtime behavior. Tiers are actionable: MEDIUM triggers verification, LOW triggers decomposition, NONE triggers refinement.
- **Resolution proof** — Every dispatch includes a serializable `ResolutionProof` trace documenting exactly why a tool was chosen, with per-step timing.
- **Pre-flight verification (Pillar 2)** — `respondsToSelector:` gate between resolution and execution. Three progressive strategies: schema validation, keyword overlap, and optional LLM micro-check.
- **Intent decomposition (Pillar 3)** — `doesNotUnderstand:` handler for LOW-confidence dispatches. Complex intents are broken into sub-intents and dispatched individually with dependency resolution.
- **Refinement protocol (Pillar 4)** — `forwardInvocation:` dialogue for NONE-confidence dispatches. Returns structured `tool_refinement_needed` result type with options for the caller to narrow the intent.
- **Observation & adaptation (Pillar 5)** — KVO-inspired dispatch observer that tracks correction signals, schema rejections, and adapts per-tool-class thresholds in real-time.
- **Pluggable LLM interface** — `LLMClient` interface for verification, decomposition, and refinement. All LLM features degrade gracefully without a client.
- **Collision firewall** — Compiler now detects and warns on tool pairs in the 0.75–0.95 similarity zone (expanded from 0.89–0.95). Dispatches in this zone trigger MEDIUM-confidence verification.
- **`--strict` mode** — Compile flag that raises thresholds, enables verification on every dispatch, and treats ambiguity as error.
- **Negative examples** — Observer tracks known-bad intent+tool pairs and skips them during resolution.
- **Adaptive thresholds** — Per-tool-class threshold tuning based on observed correction signals and schema rejections.
- **MCP `tool_refinement_needed` result type** — New result type for MCP clients to present refinement options to users.

### Changed
- **Dispatch pipeline** — `resolveToolIMP` now branches on confidence tiers instead of binary match/fallback
- **Vector search threshold** — Lowered to 0.60 (from 0.75) to capture LOW-tier candidates for decomposition
- **DispatchContext** — Now accepts `DispatchConfig` with LLM client, strict mode, thresholds, and observer options
- **RuntimeOptions** — Extended with `llmClient`, `strict`, `thresholds`, and `observerOptions`
- **MCP server** — Version bumped to 0.4.0, tool call responses include confidence tier and refinement data
